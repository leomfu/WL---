# 如何更新这个网站的内容

> 写给站主自己看的。不需要懂前端，也不需要碰终端。

## 一条铁律

**所有内容都是文件，改文件就等于改网站。** 没有后台、没有数据库、没有"登录管理页面"这种东西。
你改一个文件 → 提交 → Vercel 自动重新构建 → 一两分钟后线上就变了。

---

## 三种改法，挑顺手的

### 方法一：跟 Claude 说（最省事）

在这个项目文件夹开个终端窗口，直接说人话：

- 「新闻更新一下」
- 「我写了篇文章，标题叫 XXX，内容是……」
- 「工具页把 Figma 删掉，加上 Cursor」
- 「首页那两段改成……」

Claude 会改文件、跑构建、提交推送，一条龙。**改错了也能撤回**（git 有完整历史）。

### 方法二：GitHub 网页版改（不用装任何东西，手机也能改）

你已经用这个办法建过定时任务的文件了，就是那套：

1. 打开 https://github.com/weiliang99520-a11y/WL---
2. 点进 `content` 文件夹，找到要改的文件
3. 点文件右上角的**铅笔图标**（Edit this file）
4. 改完拉到底 → 绿色 **Commit changes**
5. **等一两分钟，线上自动更新** —— 什么都不用再做

新增文件就用 **Add file → Create new file**，文件名要带完整路径，比如
`content/posts/我的第一篇.md`。

⚠️ 唯一的例外：`.github/workflows/` 下的文件必须在网页版改（本机 token 没权限）。

### 方法三：本地改（你熟悉之后）

用编辑器改 `content/` 下的文件 → 终端里 `git add -A && git commit -m "说明" && git push`。
想先看效果就跑 `npm run dev`，浏览器打开 http://localhost:3000。

## 写一篇新文章（最常用）

在 `content/posts/` 新建一个文件，比如 `第一次做网站.md`。**文件名就是网址**
（`/blog/第一次做网站`），建议用英文或拼音，比如 `first-website.md`。

内容长这样 —— 上面那段 `---` 之间的叫 front-matter，是给系统看的；下面才是正文：

```markdown
---
title: 第一次做一个网站
title_en: Building my first website
date: 2026-08-28
type: blog
tags: [记录, 前端]
lang: zh
summary: 从零到上线，以及中途所有卡住的地方。
summary_en: From nothing to live, and everywhere I got stuck.
---

正文从这里开始，直接写就行。

## 小标题这样写

段落之间空一行。**加粗**用两个星号，`代码`用反引号。

- 列表用减号开头
- 第二条
```

字段说明：

- `type`：`blog`（博客）/ `essay`（长文）/ `thought`（想法），决定它在博客页的哪个筛选下
- `lang`：这篇的原文语言，写 `zh` 就行
- `title_en` / `summary_en`：英文版页面上显示的，**不写的话英文页会显示中文原文**
  （不勉强翻译，宁可留着中文，也别机翻得别别扭扭）
- `date`：影响排序，格式 `YYYY-MM-DD`

**写完就提交**，博客列表、RSS、⌘K 搜索、sitemap 全都自动更新，不用改任何别的地方。

📌 现在 `content/posts/` 里那三篇标着 `[示例]` 的是占位，**你第一篇真文章写完，把它们删掉**。

## 加一个视频

`content/videos.json` 里照着现有的那条往数组里加：

```json
{
  "platform": "bilibili",
  "id": "BV1WHup6fEyA",
  "title": "视频标题",
  "title_en": "Video title",
  "desc": "一句话介绍",
  "desc_en": "One-line description",
  "date": "2026-08-01",
  "cover": "/images/videos/xxx.jpg"
}
```

B 站填 BV 号，YouTube 填视频 id。封面图放 `public/images/videos/` 下，不填就用深色渐变占位。

## 改完怎么确认成功了

1. GitHub 上能看到你那次提交
2. Vercel 会自动开始构建（https://vercel.com 里能看到）
3. **一两分钟后刷新网站** —— 变了就是成了
4. 没变？可能是构建失败了。JSON 少个逗号、front-matter 格式错了都会导致失败。
   打开 Vercel 看那次构建的日志，或者直接把报错截图发给 Claude。

## 最容易踩的三个坑

1. **JSON 文件里少逗号 / 多逗号** —— 整个构建会失败。改 `.json` 前先想清楚，
   或者干脆让 Claude 改。markdown 文件没这个问题，随便改。
2. **只改了中文没改英文** —— `messages/` 下两个文件的键必须一一对应，缺一个会报错。
   内容类的（文章、about）没这个限制，英文缺了就显示中文。
3. **front-matter 的引号** —— 标题里有冒号 `:` 或方括号时必须用引号包起来，
   比如 `title: "记录：第一天"`。
