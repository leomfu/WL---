# 如何往网站上加照片

> 写给站主自己看的。不需要懂前端。
> 摄影板块在 https://weiliang.dev/zh/photos/ ，侧边栏「作品 → 摄影」。

## 先弄明白两件事

**一、照片分两种，你自己决定每一辑算哪种：**

| | 放在哪 | 长什么样 | 什么时候用 |
|---|---|---|---|
| **专题** | 列表页上半部 | 一张大图 + 标题 + 一段话 | 你满意的、成组的作品 |
| **档案** | 列表页下半部 | 按年份排的一行行清单 | 某次出门、某个月随手拍的 |

两种点进去都是一样的：缩略图方阵 → 点开看整张。

**二、原图不进仓库。**
你把原图丢进 `photos-src/`（这个文件夹只在你电脑上，不会上传），
跑一条命令，它会压出两种小图放进网站：网格里那张（宽 600）和点开放大那张（长边 2000）。
一张 5MB 的原图压完大约 100–300KB。**这一步不能跳过** —— 原图直接上传，
仓库会越滚越大，而且别人打开你的摄影页要等很久。

## 完整步骤（第一次照着做一遍就会了）

### 第 1 步：把照片放进 photos-src/

在项目文件夹（`个人网页/`）里建一个 `photos-src` 文件夹，**一辑一个子文件夹**，
文件夹名用**英文小写 + 短横线**，因为它会变成网址的一部分：

```
个人网页/
  photos-src/
    busan-2025/          ← 会变成 weiliang.dev/zh/photos/busan-2025/
      IMG_0001.jpg
      IMG_0002.jpg
      ...
```

- 照片名随便，**但顺序按文件名排**（IMG_0001 排在 IMG_0002 前面）。想调整顺序就改文件名，
  比如 `01-xxx.jpg`、`02-xxx.jpg`。
- 支持 jpg / png / webp / tiff / avif。
- ⚠️ **iPhone 的 HEIC 读不了**。在「照片」App 里选中 → 文件 → 导出 → 导出未修改的原始文件时选 JPEG；
  或者在 iPhone 上「设置 → 相机 → 格式 → 兼容性最佳」，以后拍的就直接是 jpg。

### 第 2 步：跑一条命令

在项目文件夹开终端，输入：

```
npm run photos
```

它会告诉你处理了几辑几张。跑完你会多出两样东西：

- `public/images/photos/busan-2025/` —— 压好的图（这些**会**进仓库）
- `content/photos/busan-2025.json` —— 这一辑的资料卡，标题地点日期还是空的

### 第 3 步：填资料卡

用任何编辑器打开 `content/photos/busan-2025.json`，把上面几行填掉：

```json
{
  "slug": "busan-2025",
  "kind": "archive",
  "title": "釜山",
  "titleEn": "Busan",
  "location": "韩国釜山",
  "locationEn": "Busan, Korea",
  "date": "2025-10-04",
  "dateEnd": "2025-10-06",
  "summary": "三天，海边，天气一直很好。",
  "summaryEn": "Three days by the sea.",
  "photos": [ ... 这一段别动，是命令自动写的 ... ]
}
```

| 字段 | 填什么 |
|---|---|
| `kind` | `"feature"` = 专题（大图卡片）／`"archive"` = 档案（按年份的清单） |
| `title` / `titleEn` | 中文标题 / 英文标题。**两个都要填**，网站是双语的 |
| `location` / `locationEn` | 地点，不想写就留空字符串 `""` |
| `date` | 拍摄日期，`年-月-日`，例如 `2025-10-04` |
| `dateEnd` | 拍了好几天才填，只有一天就留 `""` |
| `summary` / `summaryEn` | 一两句话，不想写就留 `""` |
| `photos` | **别手改**，`npm run photos` 会重写这一段 |

想给某一张单独配一句话，在 `photos` 里那一条上加 `caption` / `captionEn`：

```json
{ "file": "img-0007.webp", "width": 2000, "height": 1333,
  "caption": "凌晨四点的鱼市", "captionEn": "Fish market, 4am" }
```
（这两个字段**下次跑命令不会丢**，其他字段会被重写。）

### 第 4 步：看一眼，然后提交

```
npm run dev
```
浏览器打开 http://localhost:3000/zh/photos/ 看看对不对。没问题就：

```
git add -A
git commit -m "摄影：加了釜山那一辑"
git push
```

一两分钟后线上就有了。

## 以后再加照片

- **同一辑补几张**：往 `photos-src/busan-2025/` 里再丢几张 → `npm run photos` → 提交。
  （已经压过的不会重压，只处理新的，很快。）
- **新开一辑**：新建一个文件夹，重复第 1–4 步。
- **删一辑**：删掉 `content/photos/那一辑.json` 和 `public/images/photos/那一辑/` 两处，提交。
- **重压全部**（比如改了压缩参数）：`npm run photos -- --force`
- **只处理某一辑**：`npm run photos -- busan-2025`

两件你可能想改的事：

- **列表页上半部的「专题」是空的**，因为四辑都标成了 `archive`。
  想让摄影页顶上出现一张大图卡片，就把那一辑 json 里的
  `"kind": "archive"` 改成 `"feature"`，跑一次 `npm run dev` 看看。
- **青岛和上海只填了年份**（`"date": "2024"` / `"2025"`）——
  你给的文件夹名里就只有年份，照片的 EXIF 也被抹掉了，所以没法知道是几月几号。
  你记得的话，把 `date` 改成 `2024-04-20` 这种完整日期就行，页面会自动显示成 `2024.04.20`。
  多天的再填 `dateEnd`。

## 几个可能会问的

**照片是彩色的吗？** 是。全站界面只有黑白灰，但**照片本身是原色** —— 作品去色等于改了作品。

**能传多少张？** 一辑几十张没问题。压完一张大约 100–300KB，
一辑 100 张约 20MB 进仓库，这个量级 GitHub 和 Vercel 都不在乎。
真要传上千张再说，那时候该换个图床了。

**照片会被压坏吗？** 网格里那张是缩略图（宽 600，本来就是小图），
点开看的是长边 2000 的版本 —— 在任何笔记本屏幕上都是满屏清晰的。
原图（比如 6000×4000）只在你电脑上，没人需要在网页上下载 20MB 去看一张照片。

**能改成不裁成正方形吗？** 网格里的缩略图是裁成正方的（整齐），
点开看到的永远是完整未裁的整张。想改样式跟 Claude 说。

**EXIF 里的位置信息会泄露吗？** 不会。压图的时候整个 EXIF 都被丢掉了
（只有「照片朝向」被用来把竖拍的照片摆正，然后也不写进去），
所以拍摄地点、相机序列号、时间都不会跟着照片上网。
