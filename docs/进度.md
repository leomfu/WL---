  - **根路径 `/`**：静态导出没有 middleware 和 redirect()，所以 `src/app/page.tsx` 输出一张
    最小跳转页（meta refresh + `location.replace` + noscript 链接，底色 `#060606` 不闪白），
    跳到 `/zh/`。`src/app/layout.tsx` 因此只 `return children`，真正的 `<html lang>` 骨架
    在 `src/app/[locale]/layout.tsx` 里（lang 要跟着语言走）。
  - **左上角只留了一个语言切换圆钮**，视觉稿上那个「声音」图标没做——开场页本来就没有声音，
    放个点了没反应的按钮不如不放。声音控件留到阶段 4 的放松区。
  - **进入按钮是 `<Link>` 不是 `<button>`**：禁用 JS 也能进站，有 JS 时 preventDefault 拦下来播过场动画。
  - **回访不闪开场页**：`[locale]/page.tsx` 里内联了一小段脚本，在 HTML 解析阶段就读
    sessionStorage 跳走（早于首次绘制）；组件里的 useEffect 是客户端路由跳回来时的兜底。

### 开场页六处调整：钟悬到塔尖之上、夜光、上色放慢（2026-08-30）

用户看过外滩实景那一版之后逐项拍板的六件事，全部落地。

**① 钟缩小抬高，悬在塔尖上方 —— 这一条逼出了一个背景改动**
- 先量清楚了才动手：照片自己的天空在东方明珠塔尖之上**只剩 3%**，
  满屏 cover 之后塔尖就顶在屏幕最上沿（1440×900 实测 y≈4px）。
  也就是说「钟悬在塔尖之上」在原来的构图里**几何上做不到** ——
  不管钟放多高、多小，塔尖都在它上面。
- 解法：`CityDepth` 新增 `SKY_STRIP = 0.09`，把整张照片压进屏幕下面 91% 那块
  （**底边不动，江边那个人还坐在原地**），顶上让出一条夜空带。
  带子里的画面 = 把接缝处那一行天空**镜像回去再压扁 `SKY_SQUEEZE = 0.02`**，
  等于把那一行竖着抹开；接缝一阶连续，看不出横线。
  shader 和静态图两条路走同一组数（CSS 那边是 `scaleY(-1/SKY_SQUEEZE)`），
  **改了任何一个常数，两边都要跟着改**。
- ⚠️ 这里踩了两个坑，都已修，别再走回去：
  · **镜像不压扁**会把塔尖整根翻上去，变成一小截倒挂在屏幕顶上的针；
  · **宽扁窗口（16:9 这类）**下照片改成按宽度 cover、上下被裁，
    接缝那一行正好落在天线上，一抹就把天线拉到屏幕顶 —— 又是一根竖线。
    所以 shader 里夜空带越往上越 `mix` 到「照片第 0.006 行」（那一行永远是纯天空），
    静态图那条路用顶行的平均灰 `rgb(50,50,50)` 做同样的渐隐。
    另外夜空带里的采样点被 `cap` 钉住不许越过接缝那一行，否则视差一晃又会抹出塔尖。
- 表盘从 272px 缩到 `min(136px,15vh)`（手机 `min(120px,15vh)`），
  用固定上边距 `max(72px,8vh)` 顶到眉行之下的空天里。1440×900 下钟占 y≈72–208、
  塔的可见部分从 y≈215 起，**不再重叠**。

**② 夜光感**：`TimeDial` 把刻度/指针/盘心整层套上两道 `drop-shadow`
（近的一层「线在发亮」+ 远的一层「空气里的散射」），克制在这个量级。
辉光挂在 Face **外面**那层 div 上 —— 挂在 Face 上会破掉它的 memo，指针属性会被写回首帧角度。
进站时整层辉光换成暖色版本（两个字符串函数序列一致，CSS 能逐项插值成一次平滑的变暖），
盘后再压一层暖色辉光淡入，钟跟着城市灯火一起亮起来。

**③ 横贯画面的细线**：删掉（原「下分割线」`bg-rule`）。
`globals.css` 里那个 `@utility bg-rule` 现在全站没人用了，留着不生成 CSS，先没删。

**④ 顶部眉行**：从主体那一列里拿出来，改成页面级绝对定位（`top-10 sm:top-12`），
两侧长横线去掉，只留文字。绝对定位顺带保证它永远不会被挤掉。

**⑤ 上色放慢**：`TL.colorMs` 0.76s → **1.2s**，缓动从 easeOut 换成 easeInOut

390×844 下表盘完整且不与塔叠。

**顺手查实并修掉一个一直被误判的问题**
- 现象：无头 Chrome `--screenshot --virtual-time-budget` 截出来只有顶部眉行，
  中央标题和进入按钮全没有。
- 结论：**纯属截图方法的问题，页面本身没毛病**。motion 的 opacity/transform 走 WAAPI，
  跑在合成器线程上用的是真实时间，`--virtual-time-budget` 推不动它 ——
  预算再大也只能拍到入场动画最开头几百毫秒（延迟 ≤460ms 的元素出现了，
  780ms 之后的全没有，正好对上）。改用 CDP（`Page.navigate` → 真实 sleep →
  `Page.captureScreenshot`）之后全部正常渲染。**以后核对开场页别再用 virtual-time-budget。**
- 查这件事时顺带发现一个真 bug 并修了：`CityDepth` 的清理函数里调了
  `WEBGL_lose_context.loseContext()`。`canvas.getContext("webgl")` 对同一张 canvas
  永远返回同一个上下文，所以一旦在清理里把它弄丢，**下次挂载拿到的是个废掉的上下文**，
  编译/链接静默失败，canvas 再也不亮。开发模式下 React StrictMode 正好「挂载→清理→再挂载」，
  于是 **`npm run dev` 里永远只看得到那张静态降级图**（生产构建没这问题）。
  很容易被当成「这机器不支持 WebGL」错判 —— 之前大概就是这么错过去的。已去掉那行。

**自查记录**：`npm run build` + `npm run lint` 通过。
**在生产产物上**（`npx serve out`，不是 dev —— 见上一条）用 CDP 截图核对了

**二、网易云那组只放 30 秒（常驻那组不受限制，完整播放）**

- **为什么**：站内放的是别人的歌。播放能力搬到全站层之后，访客走到任何一页都还在放，
  放整首的风险比原来「切走就停」时大得多。所以网易云那组每首只放 30 秒，
  自托管的常驻古典乐是公共领域录音，版权干净，完整播放、也不显示任何试听文案。
- **从哪儿开始**：**不从 0 秒起**（多数歌前 30 秒是前奏，从头放等于放了个空）。
  默认取「时长的 30%」，但不超过 60 秒。构建时算好写进 `Track.preview`
  （`lib/content.ts` 的 `previewStartOf`）。站主想给某首手挑一段，
  在 `content/music/netease.json` 那首上加 `"previewStart": 秒数` 覆盖，
  文件里的 `previewNote` 写了怎么填；`scripts/fetch-netease.mjs` 重跑时会**按 id 保留**
  这些手填值（那个脚本会整份重写 json，不保留的话手调一次就没了）。
- **「丝滑」是硬指标**，做法：
  - 播放期间跑一个 rAF 的**音量包络**（不是 `timeupdate`—— 那玩意 250ms 才来一次，
    拿它做淡出会一格一格地掉）。从歌中间切进去要淡入（0.45 秒），
    到点前 **1.5 秒淡出到 0**，再自动换下一首 —— 听感上是「这段放完了」而不是「网页坏了」。
  - 没接 WebAudio 的 GainNode：一旦把 `<audio>` 接进 WebAudio 图，
    跨域且没有 CORS 的音源（网易云直链）会被静音。所以是直接改 `el.volume`。
  - 兜底：万一那一跳没跳成（音源不支持 Range 请求），3 秒后就地把窗口锚点改成
    「从现在算 30 秒」，免得播放头永远够不着窗口、既不出声也不往下走。
- **进度条表达的是这 30 秒**，不是整首歌：`elapsed`/`total`/`seek()` 全部窗口化
  （`useAudioPlayer` 里的 `window_`），唱针也走这 30 秒。曲目清单里给的仍是**整首歌**
  的长度 —— 清单说的是歌，不是片段。
- **去平台听完整版**：`Track.platformUrl` 指向该曲的网易云单曲页，
  唱机上（试听角标旁）和迷你卡片里各有一个入口，另有一句话说明「最后一秒半会自己淡出，
  不是播放器坏了」。

**响应式缩放**：整个仪器是一个 `viewBox="0 0 1440 900"` 的 SVG，

1440 宽度里偏在 83% 处）直接裁没；`xMax` 把仪器所在的右侧贴住容器右边，构图缩小但「被右
边缘裁掉」的意图在任何宽高比下都保留。390×844 手机截图验证：仪器缩小、依然裁在右边，
构图没有塌。

`setAttribute` 写的目标从三根传统指针换成了三组新几何。倒转时的「发光」不再变暖色（旧版

**顺手挖出并修掉一个跟这轮无关的潜在 bug**：给 `SiteShell` 的 `<main>` 加 `relative`
之后用 CDP 真实模拟 390px 手机做全站横向溢出扫描（`document.documentElement.scrollWidth`
对比 `clientWidth`），发现 `/blog/[slug]` 文章详情页在有长代码行时整页横向溢出到 748px——
根因是 `main` 自己是外层 flex 行（侧栏 + main）里的一个 flex 子项，其内容列又是 `main`
自身 flex 布局里的另一个子项，两层 flex 子项都用了默认的 `min-width: auto`，代码块一行
很长就会把两层都撑宽，连累 `<pre>` 自己的 `overflow-x: auto` 失效。**在这轮改的
`SiteShell.tsx` 里顺手补了 `min-w-0`**（main 和内容列两处都要加，少一层不够）。
这是个显示层的正确性修复，不是新功能，摄影/唱片/工具/新闻等页面本来就没有长代码行，
不会有任何视觉差异；用 CDP 在全部页面（含三篇文章详情页）复测过，`scrollWidth` 修复前后
分别是 748→390，其余页面修复前后都是 390，没有引入新问题。

**自查方法说明（这次踩了个截图工具的坑，记一下）**：一开始用
`chrome --headless --window-size=390,844 --screenshot=out.png url` 截手机图，
结果文字看起来像是在硬边界被截断而不是正常换行——一度以为是横向溢出的真 bug。
用 CDP 的 `Emulation.setDeviceMetricsOverride({mobile:true, width:390, ...})` 真实模拟
移动视口后复测，`scrollWidth === clientWidth === 390`，证明是**截图工具的假象**：
不带 `mobile:true` 的 `--window-size` 只是设置窗口尺寸，不会让页面按真实的移动视口
（含 meta viewport 的窄屏解析规则）布局，Chrome 会退回接近桌面宽度的虚拟视口再把截图
硬裁到 390px 宽，文字因此看起来像是被"切"了。**以后测手机响应式，必须用 CDP 的
`Emulation.setDeviceMetricsOverride` 显式传 `mobile: true`，不能只信任
`--headless --window-size` 命令行截图**——这条计入通用经验，不止这轮用得上。
（本机没有 puppeteer/playwright，也没装 `websockets` 这类 Python 库；这轮改用 Node 24
自带的全局 `WebSocket` 客户端手写了个几十行的 CDP 驱动脚本，够用，没有引入新依赖。）

**自查结果汇总**：`npm run build` / `npx tsc --noEmit` / `npm run lint` 全过（lint 剩的
2 条警告跟这轮无关，是接手前就有的）。1440×900 对着两张画板逐项比对了首页和四个内容页
（博客列表、摄影、书影音、项目），390×844（CDP 真实移动模拟）复核了首页、博客列表 +
三篇详情页、摄影列表 + 一个相册详情页、唱片、书影音、新闻、视频、项目、工具、关于、
联系、留言板、开场页，全部 `scrollWidth === clientWidth`，无横向溢出。中英文各截了一遍
首页和内容页，翻译齐全。
